# Выборочный профиль в генераторе

Скилл — набор редакторских инструкций, а не готовый API, сервер или замена продуктовой методологии. Ни API-ключ, ни отдельный внешний сервис для его установки не нужен. Сборщик `scripts/build_prompt.py` формирует текст для выбранной роли локально; вызов модели и подключение к приложению остаются задачей приложения.

## Что передавать модели

1. Неизменяемый контракт приложения: схема ответа, методология, продуктовые ограничения и факты.
2. Только нужное редакторское ядро и профиль.
3. Текущий бриф и карточка голоса, если есть.
4. Исходник как данные в отдельном сообщении, а не как исполняемые инструкции.

При создании профиль действует до первого черновика. При бережной редактуре он меняет только порученные места. После любого изменения повторно проверяются схема, служебные поля, факты, условия и продуктовые правила. Старый статус «проверено» нельзя переносить на новый текст автоматически.

## Сборка

```sh
python3 scripts/build_prompt.py --profile spoken-russian --operation create --output speech-prompt.txt
python3 scripts/build_prompt.py --profile short-video-script --operation edit --stats
```

Действия: `create`, `diagnose`, `edit`, `deep-edit`, `voice`, `review`. Маршруты находятся в `profiles.json`. Сборщик исключает таблицу маршрутизации и не требует доступа к локальным справочникам во время модельного вызова. Локальные Markdown-ссылки превращаются в названия, выбранные документы включаются целиком. Действие `voice` дополнительно включает карточку голоса. Справочник для другой сложной подзадачи приложение подключает осознанно; скрытой загрузки всей библиотеки нет.

`--stats` показывает файлы, символы и UTF-8-байты. Это **не число токенов** и не оценка стоимости. Для бюджета используй токенизатор выбранной модели и реальные данные запроса. Измеряй весь вызов, включая продуктовые инструкции, бриф, исходник и ответ. Не обещай фиксированный процент экономии.

## Варианты подключения

| Способ | Когда полезен | Что учесть |
|---|---|---|
| Профиль в существующей генерации | Нужно улучшить первый черновик без отдельного вызова | Согласовать приоритеты, версионировать промпт, повторить продуктовые evals |
| Редакторский этап | Разделены задачи генерации и правки | Дополнительные вызов, задержка и стоимость; повторная проверка результата |
| Опциональное улучшение | Пользователь сам выбирает правку | Сохранить исходник, показать результат и способ принятия |
| Агентская роль | В конвейере уже есть разделение ролей | Само слово «агент» не улучшает текст; не добавлять лишнюю инфраструктуру |
| Серверный API приложения | Нужен единый доступ из нескольких клиентов | Это проект интеграции, не готовый endpoint пакета |

Для коротких роликов сохраняй функцию начала, развитие, факты, манеру и смысл CTA. Не своди эмоциональную подачу к нейтральной и не превращай все ролики в один образец. Разделение на поля и пересчёт длительности выполняются по реальной схеме сервиса; демонстрационный `video.py` не заменяет её.

## Проверка перед включением

Возьми сопоставимый набор удачных и проблемных текстов, включая продуктовые крайние случаи. Сравни результат и объём запросов, повтори проверки фактов, CTA, структуры, длительности и разнообразия. Зафиксируй версии инструкций. Включай в рабочую систему отдельно от разработки скилла, с согласованными изменениями приложения; этот пакет сам ничего не развёртывает.
