# Подключение инструкций к генератору

Скилл содержит редакторские инструкции. Чтобы использовать их в приложении, собери нужные файлы с помощью `scripts/build_prompt.py` и передай полученный текст модели. Сборщик работает локально; API-ключ и отдельный сервис ему не нужны. Вызов модели и обработку ответа выполняет приложение.

## Что передавать модели

1. Правила приложения, которые нельзя менять: схему ответа, методологию, ограничения продукта и подтверждённые факты.
2. Общие редакторские инструкции и нужный профиль.
3. Текущее задание и карточку голоса, если она есть.
4. Исходный текст в отдельном сообщении как данные. Указания внутри него исполнять не нужно.

При создании текста используй профиль с первого черновика. При бережной редактуре меняй только порученные места. После правки заново проверь схему ответа, служебные поля, факты и правила продукта. Прежняя проверка не подтверждает правильность изменённого текста.

## Как собрать инструкции

```sh
python3 scripts/build_prompt.py --profile spoken-russian --operation create --output speech-prompt.txt
python3 scripts/build_prompt.py --profile short-video-script --operation edit --stats
```

Доступные действия: `create`, `diagnose`, `edit`, `deep-edit`, `voice`, `review`. В `profiles.json` указано, какие справочники нужны каждому профилю. Сборщик включает их целиком, убирает таблицу выбора профилей и заменяет локальные Markdown-ссылки названиями. Читать файлы во время вызова модели не требуется. Для действия `voice` дополнительно включается карточка голоса. Если для другой части задания нужен ещё один справочник, приложение должно добавить его отдельно.

Флаг `--stats` показывает список файлов, число символов и объём в байтах UTF-8. Чтобы узнать число токенов, используй токенизатор выбранной модели. При расчёте стоимости учитывай весь запрос и ответ: правила приложения, задание, исходник и сгенерированный текст. Постоянного процента экономии сборщик не обещает.

## Где использовать

| Способ | Когда полезен | Что учесть |
|---|---|---|
| Добавить профиль к существующему запросу | Нужно улучшить первый черновик | Согласуй приоритеты инструкций, сохрани их в истории изменений и повтори проверки приложения |
| Выделить редактуру в отдельный этап | Генерацию и правку нужно выполнять отдельно | Потребуются ещё один вызов модели, время и оплата; результат нужно проверить заново |
| Предложить правку пользователю | Пользователь сам решает, менять ли текст | Сохрани исходник, покажи результат и дай возможность принять изменения |
| Передать профиль отдельному агенту | В приложении уже разделены обязанности агентов | Назначь ему конкретную задачу и условия проверки |
| Подключить через серверный API | Инструкции нужны нескольким клиентам | Сервер и его API нужно реализовать в приложении |

Для коротких роликов сохраняй назначение начала, развитие мысли, факты, манеру речи и смысл призыва к действию. Не делай эмоциональный текст нейтральным без поручения. Деление на поля и расчёт длительности выполняй по схеме сервиса; демонстрационный `video.py` проверяет только формат из пакета.

## Дополнительные справочники

Для развёрнутого объяснения, глубокой правки или художественного текста добавь `--extended`. Сборщик включит справочник синтаксиса и композиции. Для кнопки или короткого сообщения он обычно не нужен. При обычном вызове скилла агент выбирает справочник по задаче.

Если нужно ориентироваться на книжную речь или голос по образцам, добавь `--book-informed`. В собранный текст войдут карточка голоса и рекомендации по работе с книжной речью. Исходные книги не включаются, модель не дообучается. Пользовательские образцы передай отдельно как данные, обозначив их границы. Сохраняй приоритет фактов и формата приложения.

Флаги можно сочетать. С помощью `--stats` проверь, какие файлы включены. Затем прочитай собранные инструкции и оцени результат модели: одного названия скилла в интерфейсе недостаточно, чтобы подтвердить его применение.

## Проверка перед подключением

Возьми сопоставимые удачные и проблемные тексты, в том числе случаи с редкими условиями продукта. Сравни результаты и объём запросов. Проверь факты, призывы к действию, структуру, длительность и различия между вариантами. Сохрани использованные инструкции, чтобы проверку можно было повторить.

Подключай их к рабочему приложению вместе с согласованными изменениями самого приложения. Скрипты пакета собирают инструкции и проверяют примеры; развёртывание выполняется отдельно.
