# Интеграция в проект

## Размещение

В корне пакета находятся `SKILL.md`, `references/`, `examples/`, `scripts/`: копируй **всю папку** под именем `zhivoy-russkiy`, а не один файл. Архив распаковывается в такую папку.

| Среда | Для проекта | Для пользователя | Явный вызов |
|---|---|---|---|
| Codex | `.agents/skills/zhivoy-russkiy/` | `~/.agents/skills/zhivoy-russkiy/` | `$zhivoy-russkiy` |
| Claude Code | `.claude/skills/zhivoy-russkiy/` | `~/.claude/skills/zhivoy-russkiy/` | `/zhivoy-russkiy` |

Это актуальные пути из [документации Codex](https://learn.chatgpt.com/docs/build-skills) и [Claude Code](https://code.claude.com/docs/en/skills), сверенные 22.10.2026. В некоторых существующих установках Codex встречается `~/.codex/skills`; проверяй обнаружение в своей версии. Не устанавливай две одноимённые копии в разные места без необходимости. Если скилл не появился, обнови список навыков или перезапусти сессию.

Из папки, **содержащей** скачанный `zhivoy-russkiy`, установка для проекта Codex:

```sh
mkdir -p /path/to/game/.agents/skills
cp -R -n zhivoy-russkiy /path/to/game/.agents/skills/
```

Для Claude Code замени `.agents` на `.claude`. `-n` не перезаписывает существующие файлы; для обновления сначала сравни версии и сохрани свои изменения. Не накладывай новую версию поверх старой без проверки оставшихся файлов. Абсолютный `/path/to/game` — место твоего проекта, не готовая команда для запуска без подстановки.

Проверка установки: попроси агента использовать скилл и назвать путь прочитанного `SKILL.md`, затем отредактировать один небольшой пример. Если автоактивация не сработала, используй явный вызов. Это не требует API-ключей, Telegram, GitHub или дополнительных Python-пакетов.

## Подключение к игровому процессу

1. Прочитай правила репозитория. Найди исходные строки, а не сгенерированный экспорт; проверь, не записана ли уже озвучка.
2. Возьми небольшую целую сцену со входом, выбором и схождением ветвей. Прочитай глоссарий и карточки голосов.
3. Зафиксируй неизменяемые поля и служебные конструкции. Сохрани исходную версию для сравнения.
4. Отредактируй только строки в порученном объёме. Проверь каждую ветку в контексте.
5. Выполни проверки формата проекта и diff; затем посмотри текст в игре, если запуск доступен и поручен. Не заявляй проверку в движке по результату JSON-валидатора.

Подход по форматам:

| Формат | Что учитывать |
|---|---|
| JSON / JSONL | ID, типы, escape-последовательности; редактировать значения нужных полей, не сериализовать весь проект без нужды |
| Ren'Py `.rpy` | Блоки и отступы Python, метки, `menu`, интерполяцию, теги; использовать проверки Ren'Py |
| Ink / Yarn | Узлы, отступы, условия, метки строк и переходы; проверять компилятором проекта |
| Godot CSV / PO | Ключи, контекст, множественные формы и разделитель; не открывать как произвольный текстовый список |
| Unity localization | GUID/ключи, Smart Strings, plural/select, метаданные; нужен форматный валидатор Unity |

Скилл даёт редакторские инструкции для этих сред, но **не поставляет их парсеры**.

## Формат встроенного валидатора

Демонстрационные `examples/scene.before.json` и `scene.after.json` имеют объект в корне и массив `lines`. Каждая строка — объект с уникальным непустым строковым `id` и строкой `text`; остальные поля произвольны и полностью неизменяемы. Необязательный `max_chars` — неотрицательное целое. Валидатор разрешает менять только `lines[i].text`; порядок строк фиксирован. Дубликаты ключей JSON отвергаются.

Поддерживается узкое, явно определённое подмножество вставок:

- `{name}`, `{player.name}`, `{0}`, `{name!r}`, `{count:03d}`; одинаковое число вхождений каждого токена, разрешена перестановка именованных/индексированных вставок;
- литеральные `{{` и `}}` — сохраняется количество; любые другие фигурные конструкции, включая ICU plural/select, вызывают отказ;
- printf `%s`, `%d`, `%0.2f`, `%2$s`, `%(name)s`, `%%` с обычными флагами и шириной; вся последовательность printf сохраняется консервативно. Другие диалекты проверяй отдельно;
- угловые теги вроде `<b>`, `</b>`, `<color=red>` — точная последовательность;
- число переводов строки, табуляций и буквальных `\n`, `\t`, `\r`; неизвестные управляющие символы отвергаются.

Ren'Py-теги вроде `{w}` могут выглядеть как именованные вставки, но валидатор не знает их временной семантики: используй проверки движка. Квадратные вставки `[name]`, Markdown-ссылки, BBCode, JSON-строки со встроенным кодом и управляющие команды не поддерживаются этим контрактом.

Лимит `max_chars` измеряется Python `len`: кодовые точки Unicode, включая вставки и теги. Это не пиксели, не байты и не длина после подстановки имени. Значение лимита задаёт проект; инструмент его не угадывает.

Запуск из папки пакета:

```sh
python3 scripts/quality.py compare examples/scene.before.json examples/scene.after.json
python3 scripts/quality.py lint examples/scene.before.json
python3 -m unittest discover -s tests -v
```

Коды завершения: `compare` — 0 при успехе, 1 при нарушении, 2 при ошибке входных данных/неподдержанном синтаксисе. `lint` — 0 даже при находках (они информационные), 2 при ошибке чтения. Никакие файлы эти команды не меняют.

## Небольшая постоянная подсказка

Если нужно, добавь в существующий `AGENTS.md` или `CLAUDE.md` согласованное правило, сохранив остальные инструкции:

> Для русских диалогов и пояснений используй установленный zhivoy-russkiy. Сохраняй канон, голоса, ключи локализации и управляющие вставки. Источник строк, глоссарий и карточки персонажей ищи в документации этого проекта. Не переписывай намеренный канцелярит персонажей.

Codex: `$zhivoy-russkiy Отредактируй эту сцену бережно: убери переводной слог, сохрани сомнение Лиды и все переходы. Сначала прочитай карточки персонажей.`

Без поддержки навыков: передай модели `SKILL.md` как инструкции и нужный справочник вместе с исходником. Это ручной перенос; автоматического обнаружения и исполнения скриптов он не обещает.
