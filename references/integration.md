# Установка и работа с проектом

## Размещение

Копируй **всю папку** `zhivoy-russkiy`: вместе с `SKILL.md` нужны справочники и остальные файлы пакета. Если после распаковки архива папка называется `zhivoy-russkiy-main`, переименуй её в `zhivoy-russkiy`.

| Среда | Для проекта | Для пользователя | Явный вызов |
|---|---|---|---|
| Codex | `.agents/skills/zhivoy-russkiy/` | `~/.agents/skills/zhivoy-russkiy/` | `$zhivoy-russkiy` |
| Claude Code | `.claude/skills/zhivoy-russkiy/` | `~/.claude/skills/zhivoy-russkiy/` | `/zhivoy-russkiy` |

Пути описаны в [документации Codex](https://learn.chatgpt.com/docs/build-skills) и [Claude Code](https://code.claude.com/docs/en/skills). В некоторых установках Codex также используется `~/.codex/skills`. Проверь, где твой клиент ищет скиллы, и не создавай несколько одноимённых копий без необходимости. Если скилл не появился, обнови список навыков или перезапусти сессию.

Чтобы установить скилл для проекта Codex, перейди в папку, **внутри которой** лежит скачанный `zhivoy-russkiy`, и выполни:

```sh
mkdir -p /path/to/project/.agents/skills
cp -R -n zhivoy-russkiy /path/to/project/.agents/skills/
```

Вместо `/path/to/project` укажи полный путь к своему проекту. Для Claude Code замени `.agents` на `.claude`. Флаг `-n` сохраняет существующие файлы. Перед обновлением сравни установленную папку со скачанной и сохрани собственные правки. При замене проверь, не остались ли файлы, которых больше нет в репозитории.

Для проверки попроси агента использовать скилл, назвать путь прочитанного `SKILL.md` и отредактировать небольшой пример. Если агент не выбрал скилл сам, вызови его по имени. Дополнительные пакеты для работы скилла не нужны.

## Подключение к любому проекту

Определи, какие тексты поручено создать или исправить: страницы сайта, подписи в интерфейсе, письма, статьи, документацию, прозу или диалоги. Прочитай исходные материалы, выясни, кому и от чьего имени пишешь, найди глоссарий. Сохрани подтверждённые факты и требования к формату. В кодовом проекте редактируй исходники или файлы локализации. Для интерфейса используй [соответствующий справочник](web-ui.md), для статьи или письма — [рекомендации по выбору регистра](registers.md).

На сайте проверь подписи, действия кнопок, условия продукта и имена элементов для программ чтения с экрана. В письме сверь просьбу, срок и тон обращения. В статье проследи ход аргументов, проверь источники и убедись, что автору не приписан выдуманный опыт. Для кода и форматов используй технические проверки. Качество литературного текста оценивай по смыслу и звучанию.

## Пример: работа над игровой сценой

1. Прочитай правила репозитория. Найди исходные строки, а не сгенерированный экспорт; проверь, не записана ли уже озвучка.
2. Возьми небольшую целую сцену: от начала через выбор до места, где сходятся ветви. Прочитай глоссарий и карточки голосов.
3. Отметь поля и служебные конструкции, которые нельзя менять. Сохрани исходник для сравнения.
4. Отредактируй порученные строки. Прочитай каждую ветку целиком.
5. Запусти проверки формата проекта и просмотри изменения. Затем проверь текст в игре, если запуск доступен и поручен. Результат JSON-валидатора не подтверждает, что сцена проверена в движке.

Что учитывать в разных форматах:

| Формат | Что учитывать |
|---|---|
| JSON / JSONL | ID, типы и управляющие последовательности; меняй значения нужных полей, не перезаписывай весь проект без необходимости |
| Ren'Py `.rpy` | Блоки и отступы Python, метки, `menu`, подстановки и теги; используй проверки Ren'Py |
| Ink / Yarn | Узлы, отступы, условия, метки строк и переходы; проверяй компилятором проекта |
| Godot CSV / PO | Ключи, контекст, множественные формы и разделитель; сохраняй структуру таблицы или каталога переводов |
| Unity localization | GUID и ключи, Smart Strings, plural/select и метаданные; проверяй средствами Unity |

В скилле есть рекомендации по редактуре в этих средах. Парсеры и проверки предоставляет сам проект.

## Формат встроенного валидатора

В демонстрационных файлах `examples/scene.before.json` и `scene.after.json` корневой объект содержит массив `lines`. Каждый элемент массива содержит уникальный непустой строковый `id` и строку `text`. Остальные поля могут быть любыми, но менять их нельзя. Необязательное поле `max_chars` содержит неотрицательное целое число. Валидатор разрешает менять только `lines[i].text`, сохраняя порядок строк. Повторяющиеся ключи JSON считаются ошибкой.

Валидатор поддерживает только перечисленные виды вставок и служебных конструкций:

- `{name}`, `{player.name}`, `{0}`, `{name!r}`, `{count:03d}`; число вхождений каждой вставки должно сохраняться, именованные и индексированные вставки можно переставлять;
- буквальные `{{` и `}}` — их количество должно сохраняться; другие конструкции в фигурных скобках, включая ICU plural/select, не поддерживаются;
- printf `%s`, `%d`, `%0.2f`, `%2$s`, `%(name)s`, `%%` с обычными флагами и шириной; порядок и написание всех вставок printf должны точно сохраняться. Другие диалекты проверяй отдельно;
- угловые теги вроде `<b>`, `</b>`, `<color=red>` — их порядок и написание должны точно сохраняться;
- число переводов строки, табуляций и буквальных `\n`, `\t`, `\r`; неизвестные управляющие символы считаются ошибкой.

Теги Ren'Py вроде `{w}` могут выглядеть как именованные вставки, но валидатор не проверяет, как они влияют на время показа реплики. Используй проверки движка. Квадратные вставки `[name]`, Markdown-ссылки, BBCode, JSON-строки со встроенным кодом и управляющие команды этим валидатором не поддерживаются.

Для проверки `max_chars` используется Python `len`: подсчитываются кодовые точки Unicode, включая вставки и теги. Ширина в пикселях, размер в байтах и длина после подстановки имени здесь не измеряются. Лимит задаёт проект; инструмент не выбирает его самостоятельно.

Запуск из папки пакета:

```sh
python3 scripts/quality.py compare examples/scene.before.json examples/scene.after.json
python3 scripts/quality.py lint examples/scene.before.json
python3 -m unittest discover -s tests -v
```

Коды завершения `compare`: 0 — проверка пройдена, 1 — найдено нарушение, 2 — ошибка входных данных или неподдерживаемый синтаксис. Команда `lint` возвращает 0 и при найденных замечаниях: они носят справочный характер. При ошибке чтения она возвращает 2. Команды не меняют файлы.

## Небольшая постоянная подсказка

Если нужно, добавь в существующий `AGENTS.md` или `CLAUDE.md` согласованное правило, сохранив остальные инструкции:

> При создании и редактуре русских текстов используй установленный zhivoy-russkiy: для сайта, интерфейса, писем, статей, объяснений, прозы и диалогов. Выбирай манеру речи с учётом задачи и адресата. Сохраняй факты, голос, условия продукта, ключи локализации и управляющие вставки. Упрощай стиль только там, где это нужно для задания.

## Примеры запросов

Codex: `$zhivoy-russkiy Отредактируй эту сцену бережно: убери переводной слог, сохрани сомнение Лиды и все переходы. Сначала прочитай карточки персонажей.`

Claude Code: `/zhivoy-russkiy Объясни механику выносливости по указанным правилам. Дай полную подсказку и короткую строку для интерфейса, не добавляй новые условия.`

Если клиент не поддерживает скиллы, передай модели `SKILL.md` и нужный справочник как инструкции, а исходный текст — отдельно как данные. При таком подключении справочники выбираешь ты; скрипты сами не запускаются.

## Профили и другие агенты

Выбирай профиль по задаче с помощью таблицы в [SKILL.md](../SKILL.md). Отдельная установка или команда для него не нужна. Для приложения или другого агента можно [собрать выбранные инструкции](prompt-integration.md) в один текст. При изменении проекта сохраняй его формат и запускай штатные проверки. [Условия проверки видеосценария](script-contract.md) относятся только к демонстрационному формату пакета.
