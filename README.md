# Живой русский

Переносимый редакторский скилл для **Codex и Claude Code**: естественные русские игровые диалоги, индивидуальные голоса, художественная редактура и ясные объяснения.

Он помогает убрать ощущение текста, переведённого с английского, сохраняя смысл, характер и устройство игры. Приёмы советской редакторской и учебной традиции используются выборочно: конкретность, точность слова, выразительность, последовательность мысли. Скилл не навязывает идеологию, архаизмы или подражание автору.

**Версия 1.0.0 · Python 3.10+ нужен только для необязательных проверок.** Скилл работает как набор инструкций; он не дообучает модель и не требует книг, Telegram, API-ключа или доступа к GitHub.

## Быстрый старт

Скопируй всю папку `zhivoy-russkiy` в выбранное место:

| | В проект | Для всех проектов пользователя |
|---|---|---|
| Codex | `.agents/skills/zhivoy-russkiy/` | `~/.agents/skills/zhivoy-russkiy/` |
| Claude Code | `.claude/skills/zhivoy-russkiy/` | `~/.claude/skills/zhivoy-russkiy/` |

Вызови в Codex:

```text
$zhivoy-russkiy Отредактируй диалоги этой сцены: убери переводной слог,
сохрани смысл, голоса и все служебные вставки. Правка бережная.
```

В Claude Code:

```text
/zhivoy-russkiy Отредактируй эту сцену по тем же условиям.
```

Для проверки обнаружения попроси назвать путь загруженного `SKILL.md`. Подробности установки, обновления и интеграции с движком — в [инструкции](references/integration.md). Пути сверены с [официальной документацией Codex](https://learn.chatgpt.com/docs/build-skills) и [Claude Code](https://code.claude.com/docs/en/skills) 22.10.2026.

## Что меняется в тексте

**Черновик:** «Я не думаю, что это то, что мы должны делать прямо сейчас».

**Правка для сомневающейся Лиды:** «Не знаю, стоит ли сейчас за это браться».

Она по-прежнему сомневается. Реплика «Не трогай!» была бы сменой смысла, даже если она короче.

У разных персонажей различаются не только слова, но и внимание, отношения и речевое действие. Мастер называет устройство и действие, ученица предлагает решение, диспетчер фиксирует условие допуска. Это пример карточек, а не правило о профессиях. Естественная русская речь может быть мягкой, строгой, длинной, современной, смешной или нарочито казённой — по задаче.

## Проверки

Из папки пакета:

```sh
python3 -m unittest discover -s tests -v
python3 scripts/quality.py compare examples/scene.before.json examples/scene.after.json
python3 scripts/quality.py lint examples/scene.before.json
```

Команды только читают данные. `compare` проверяет конкретный простой JSON-контракт, вставки, теги, переходы и лимиты. `lint` предлагает места для размышления; автоматических замен и списка запрещённых слов нет. Ни один скрипт не определяет художественное качество и не заменяет проверки игрового движка. Для Ren'Py, Ink, Yarn, Godot и Unity описаны правила работы, но их парсеры в пакет не входят.

Для других форматов агент сохраняет техническую структуру по правилам проекта. Сначала проверь одну сцену и её ветви, затем распространяй согласованные решения. Не отправляй проект внешним оценщикам без разрешения.

## Источники и права

Основа — точечное чтение доступных фрагментов редакторской книги Норы Галь, научной популяризации Перельмана и учебника под редакцией Ландсберга; точные ссылки и ограничения — в [реестре](references/sources.md). Это не репрезентативный корпус советской литературы. Telegram-страница @sovuche доступна, но книги канала не получены и не использованы.

Все демонстрации написаны для пакета. Полные книги, сканы и чужие упражнения не распространяются. Лицензия MIT относится к оригинальным материалам и коду пакета, а не к внешним книгам и сайтам.

## Публикация на GitHub

Пакет готов как содержимое отдельного репозитория. На момент подготовки удалённый репозиторий **не создан**: проверка GitHub API показала пользователя `targetessa`; запрос к указанному `misorarui` вернул 404. Это не доказывает, что аккаунта никогда не было, и не даёт права выбрать другого владельца вместо пользователя.

Предлагаемое имя — `zhivoy-russkiy`. Перед публикацией нужно подтвердить владельца и видимость, затем проверить право создания репозитория. Не загружать тестовые данные игры, локальные токены и служебную историю чата.

После подтверждения для владельца `OWNER` (заменить на подтверждённый аккаунт), из папки пакета при установленном и авторизованном GitHub CLI:

```sh
git init -b main
git add .
git commit -m "Add Zhivoy Russkiy skill"
gh repo create OWNER/zhivoy-russkiy --private --source=. --remote=origin --push
gh repo view OWNER/zhivoy-russkiy --json nameWithOwner,url,isPrivate,viewerPermission
git ls-remote origin refs/heads/main
```

Пример создаёт закрытый репозиторий. Публичный выбирается отдельно. Если локальная история уже есть, не запускай инициализацию повторно. Настройки автора коммитов должны быть настроены владельцем. Успех публикации подтверждают просмотр репозитория и совпадение удалённого коммита с локальным, а не только успешный локальный коммит.

## Развитие

Предлагай улучшения вместе с контекстом: исходник, предполагаемая правка, канон, голос, эффект. Не добавляй универсальный запрет из одного неудачного оборота. Новое правило должно улучшать решение на проверяемом примере и не портить намеренный стиль. Для технических изменений запускай тесты; для редакторских — проверяй сохранение смысла и задания из `evals/`.

Скилл улучшает рабочий процесс, но не гарантирует качество любого ответа любой модели. Оценивай результат по конкретному тексту.
